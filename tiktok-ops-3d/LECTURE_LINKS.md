# 관제실 ↔ 강의 연결 노트

> TikTok 5폰 관제실(`index.html`)이 강의에서 배운 어떤 개념을 화면으로 옮긴 것인지 정리했다.
> 강의 원문은 옮기지 않고 **내 말로 풀어 쓴 요점**만 적는다. 근거 파일은 `강의노트/` 기준 상대 경로.

## 한눈에 — 관제실은 "에이전트 팀" 그림이다

비유: **식당 주방**.
매니저 로봇은 주방장(주문을 나눠 줌), 폰 5대는 각자 화구를 맡은 요리사,
TikTok 서버는 손님 테이블(요리를 받아 감)이다. 요리사는 다 만들면 주방장에게 "완료"를 외친다.

이걸 강의 용어로 바꾸면:

| 관제실 화면 | 강의 용어 | 배운 날 |
|---|---|---|
| ASTRO-M 로봇 | 오케스트레이터(지휘자) | 10-27 · 10-19 |
| 폰 5대 | 워커(일꾼) — 각자 독립된 맥락 | 10-27 · 11-04/06 |
| 하루 6회 + 오후 1회 일정 | 정해진 워크플로 + 스케줄(cron) | 10-15 · 10-20 · 10-28 |
| 청록 명령 → 분홍 보고 | 계획 → 실행 → 관찰 루프 | 09-07 · 10-16 |
| TikTok 서버(피드·업로드·완료 확인) | 도구 / 백엔드 엔드포인트 | 09-03 · 10-21 |
| 통신 로그 · 일정표 | 실행 기록(trajectory) · 관측 로그 | 10-16 · 10-12 |
| 활성화 6/6 카운터 | 상태(state) · 중복 실행 방지 | 09-04 · 09-08 |

## 1. 에이전트 팀 구조 — 지휘자와 일꾼

**10-27 에이전트 팀 꾸리기 (LangGraph)**
- 일을 나누는 네 가지 모양: 순서대로 잇기 · 갈림길로 보내기 · 동시에 돌리기 · **지휘자-일꾼**.
- 지휘자가 일을 여러 일꾼에게 한꺼번에 뿌리고, 돌아온 결과를 하나의 상태에 합친다.
- 관제실: 로봇이 5대에 명령을 뿌리고(`tickSim` → `send(i,'R',true,'cmd')`), 보고가 오면 오늘 집계(`stats`)에 더한다. **가장 직접적인 대응.**
- 근거: 강의 원본 폴더의 단계 제목·코드만 확인(노트 없음).

**10-19 멀티 에이전트** — `강의노트/2026-10-19/summary.md`
- 혼자 하는 에이전트 / 코드로 짠 워크플로 / 지휘 모델 셋을 비교한다.
- 일을 쪼개기 전에 묻는다: 각 조각을 **따로 탐색**할 수 있나? **따로 검증**할 수 있나?
- 관제실: 계정마다 시간대·언어·업로드가 독립이라 두 질문 모두 "예" → 쪼개는 게 맞다.

**11-04 · 11-06 딥리서치** (노트 없음, 원본 단계 제목만)
- 연구 담당 노드는 **반환 형식을 고정**하고 맥락을 따로 둔다.
- 관제실: 폰 보고가 늘 같은 모양(시청·좋아요·댓글 / 업로드 완료)이라 로봇 쪽 상태가 작게 유지된다.

## 2. 하네스 — 모델을 감싸는 작업대

**09-07 AI 에이전트 도구** — `강의노트/2026-09-07/summary.md`
- 에이전트 = 모델 + 하네스. 계획하고, 행동하고, 결과를 보고 다시 판단하는 반복.
- 관제실: 명령(행동) → 폰 작업 → 보고(관찰) → 다음 명령. 화면의 패킷 왕복이 이 반복 그 자체다.

**10-16 에이전트 하네스** — `강의노트/2026-10-16/summary.md`
- 하네스의 일곱 가지 일: 행동 형식, 맥락 관리, 기술 축적, 되돌아보기, 최소화, 권한·보안, 평가 반복.
- 도구는 논문 숫자가 아니라 **내 실행 기록**으로 판단한다.
- 관제실: 통신 로그와 일정표가 실행 기록이다. 하루 마감 줄(`D1 마감 · 활성화 30/30 …`)이 평가 지점.

**10-12 프로젝트 도구 설계** — `강의노트/2026-10-12/원본.md`
- 실패는 세 번 온다: 도구를 잘못 고를 때, 결과를 잘못 읽을 때, 같은 실수를 반복할 때.
- 최소 하네스 여섯 요소: 시스템 지시 · 도구 · 권한 · 실행 환경 · **관측 로그** · **멈춤 규칙과 사람에게 넘기기**.
- 관제실: 로그는 있다. **멈춤 규칙은 아직 없다** → 아래 "다음에 넣을 것" 참고.

## 3. 일정 — 사람이 아니라 시계가 시킨다

**10-15 자동화와 에이전트** — `강의노트/2026-10-15/원본.md`
- 핵심 질문: **다음 걸음을 누가 정하나** — 사람, 정해진 흐름, 에이전트?
- 맡길 것 · 멈출 곳 · 실패하면 볼 것을 먼저 정한다.
- 관제실: 하루 6회 + 1회는 **정해진 흐름**이다. 로봇이 판단할 일은 예외(실패·지연)뿐이어야 한다.

**10-20 Openclaw** (노트 없음)
- 게이트웨이 하나에 여러 에이전트를 올리고, 반복 작업은 cron 으로 예약한다. 상태·사용량을 모니터링한다.
- 관제실: 오른쪽 카드 패널이 모니터링, 계정별 일정이 cron 예약에 해당.

**10-28 뉴스레터 에이전트** — `강의노트/2026-10-28/1028요약.md`
- 매일 아침 자동 실행을 GitHub Actions cron 으로 걸면서 **UTC ↔ KST 변환**을 직접 했다.
- 관제실: "기준: 나라별 현지시각 / 한국시각" 버튼과 `toKst()` 가 같은 문제다.
  태국 09:00 = 한국 11:00, 대만 09:00 = 한국 10:00.

## 4. 서버와 데이터 — 화면 뒤에서 일어나는 일

**09-03 백엔드** — `강의노트/2026-09-03/summary.md`
- 요청 → 처리 → 응답. 서버는 앞단이 보낸 것을 **다시 확인**한다.
- 관제실: 폰이 영상 조각을 올리면 서버가 **게시 완료 확인**(연두 패킷)을 돌려보내고,
  그걸 받아야 폰이 로봇에 보고한다.

**10-21 에이전트와 도구 연결** (노트 없음)
- 에이전트가 도구를 부르는 방식과 MCP. "모델이 본 것과 실제로 한 것", "누가 실행했나"를 따로 본다.
- 관제실: 피드·좋아요·업로드는 **폰이 실행**하고, 로봇은 지시만 한다. 실행 주체가 화면에서 갈린다.

**09-04 데이터베이스 · 09-08 MVP** — 각 날짜 `summary.md`
- 상태를 한 번에 안전하게 바꿔야 두 번 실행되지 않는다(중복 예약 방지).
- MVP 는 한 줄기를 끝까지 먼저 완성하고, **안 만들 목록**을 따로 적는다.
- 관제실: `ev.fired` 표시로 같은 일정이 두 번 나가지 않는다. 실제 폰 조작은 PRD "하지 않는 것"에 적었다.

**09-01 웹페이지 세 겹 & 게임** — `강의노트/2026-09-01/summary.md`
- HTML·CSS·JS 세 겹, JS 는 한 줄로 일하며 이벤트 루프로 돌아간다.
- 관제실: 파일 하나에 세 겹이 다 있고, 모든 움직임이 `requestAnimationFrame` 한 루프에서 돈다.

## 5. 실패와 사람 — 아직 비어 있는 칸
