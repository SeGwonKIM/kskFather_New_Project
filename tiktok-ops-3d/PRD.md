# PRD — TikTok 5폰 관제실 (3D 시각화)

## 한 줄 요약
안드로이드 폰 5대(한국 2 · 일본 1 · 태국 1 · 대만 1)와 매니저 에이전트(로봇)가
하루 일정을 어떻게 주고받는지 **3D 게임 화면처럼** 보여 주는 단일 HTML 시뮬레이터.

> 비유: 관제탑(로봇)이 활주로의 비행기(폰 5대)에게 무전을 보내고,
> 비행기는 일을 마치면 다시 무전으로 결과를 보고한다. 그 무전이 빛나는 점으로 보인다.

## 운영 규칙 (시뮬레이션이 따르는 일정)
| 항목 | 내용 |
|---|---|
| 계정 | KR-1, KR-2(한국), JP(일본), TH(태국), TW(대만) — 폰 1대에 계정 1개 |
| 계정 활성화 | 일과 시간 중 **하루 6회** — 09:00 · 10:30 · 12:00 · 13:30 · 15:00 · 16:30 기준 |
| 동영상 업로드 | **하루 1회, 오후** — 14:00~16:00 사이 계정별로 다른 시각 |
| 시차 | 일본=한국과 같음, 대만 −1시간, 태국 −2시간 |
| 기준 시각 | 버튼으로 전환 — "나라별 현지시각"(기본) / "한국시각(KST)" |
| 겹침 방지 | 계정마다 몇 분씩 어긋나게 배치, 폰이 바쁘면 다음 일은 끝날 때까지 대기 |

## 화면 구성
1. **3D 무대 (앞 → 뒤 3단)**
   - 앞: 육각 플랫폼 위의 매니저 로봇 — 날씬한 현대형 휴머노이드(오리지널 디자인).
     진주빛 장갑, 검은 바이저와 빛나는 눈 띠, 가슴 V 라인과 코어, 등 추진기, 머리 위 회전 고리.
   - 가운데: 호(arc) 모양 받침대 위의 폰 5대.
   - 뒤: **TikTok 서버 시스템(가상)** — 높은 단 위에 중앙 코어 타워와 서버 랙 4대
     (피드 서버 · CDN 캐시 · 업로드 서버 · 분석 서버). 랙 앞면 LED 가 부하에 따라 깜빡인다.
2. **연결선 두 갈래**
   - 로봇 ↔ 폰: 명령과 결과 보고.
   - 폰 ↔ 서버: 실제 앱 트래픽. 활성화 중엔 피드가 내려오고 좋아요·요청이 올라가며,
     업로드 중엔 영상 조각이 서버로 올라간다. 서버는 게시 완료 확인을 돌려보낸다.
3. **데이터 패킷** — 청록=명령, 분홍=결과 보고, 주황 상자=영상 파일, 주황 점=업로드 조각,
   민트=피드, 연두=게시 완료 확인, 흐린 점=연결 확인(heartbeat).
4. **흐름 순서** — 로봇 명령 → 폰 ↔ 서버 작업 → (업로드면 서버 완료 확인) → 폰이 로봇에 보고.
5. 서버 코어를 클릭하거나 서버 카드를 누르면 서버 쪽으로 카메라가 이동한다.
6. **폰 화면** — 대기 / 명령 수신 / 피드 스크롤(활성화) / 업로드 % / 오늘 완료 를 실제로 그린다.
7. **HUD** — 시계·배속(60×/300×/1200×)·일시정지·다음 일정 건너뛰기, 매니저·서버·계정 카드,
   통신 로그, 하루 일정표(●활성화 6 · ◆업로드 1).

## 하지 않는 것
- 실제 폰·틱톡 계정을 조작하지 않는다. **화면 속 시뮬레이션만** 한다.
- 외부 라이브러리·빌드 도구 없음. `index.html` 하나를 열면 바로 돈다.
